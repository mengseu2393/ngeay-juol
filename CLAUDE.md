# RentWise

RentWise is a Laravel 12 + Filament 3 property-management app for Cambodian rental operators (landlords, properties, units, tenancies, rent/utility billing, maintenance, platform subscriptions). Two Filament panels (`/admin` for platform staff, `/app` for landlords), a Livewire-driven tenant portal, and Khmer-localized PDF invoices are the core surfaces. For local setup, running the app, and the feature list, see README.md — this file is conventions and footguns only.

## Coding conventions

### Backend (PHP/Laravel)

- Validate inline in the controller with `$request->validate([...])`. There are **zero** Form Request classes in this app (no `app/Http/Requests` at all) — do not create one. See `app/Http/Controllers/TenantPortalController.php`.
- Declare casts via `protected function casts(): array { return [...]; }` (Laravel 11+ method form), never `protected $casts = [...]`. 28/28 models use the method form. See `app/Models/Invoice.php`.
- Every fixed-state column is a backed native PHP enum in `app/Enums`, cast directly (`'status' => RentalStatus::class`). Enums shown in Filament UI implement `HasLabel` (+ `HasColor` for badges) with a `getLabel()`/`getColor()` match and a static `options(): array` helper. See `app/Enums/InvoiceStatus.php`. A few simpler enums never surfaced in a Filament form/table (`OccupantRole`, `MoveInCalculationType`) skip this — default to the full `HasLabel` pattern for anything user-facing.
- Any model with a `landlord_id` column uses the `BelongsToLandlord` trait (`app/Models/Concerns/BelongsToLandlord.php`), which registers the `LandlordScope` global scope and auto-fills `landlord_id` on create. Never hand-write `where('landlord_id', ...)` tenant filtering — add the trait, and implement `resolveLandlordId(): ?int` when the id must be derived from a parent relation.
- When code must intentionally cross the landlord boundary (internal FK lookups in `booted()`, cross-tenant admin reads), call `Model::withoutGlobalScopes()` explicitly rather than fighting the scope another way. See `app/Models/Rental.php` (`freeUnitIfVacant()`), `app/Models/Invoice.php` (`resolveLandlordId()`).
- Authorization for a landlord-owned resource is a one-method subclass of `LandlordOwnedPolicy`: implement only `protected function resource(): string` (the Shield permission slug). Only write a full custom policy when the resource isn't a plain landlord-owned record. See `app/Policies/InvoicePolicy.php`.
- Domain logic lives in single-purpose classes under `app/Services` (create/build/resolve/compute), resolved via `app(SomeService::class)` at the call site rather than constructor-injected into controllers. Pure/stateless helpers are `public static function` on the same service class. See `app/Services/InvoiceBuilderService.php`.
- `app/Actions` is reserved for Fortify only. New invokable action/service classes (even named `*Action`) go in `app/Services`, e.g. `app/Services/CompleteMoveInAction.php`.
- Multi-step writes wrap in `DB::transaction()` (see `InvoiceBuilderService::create()`).
- Domain-rule violations throw built-in SPL exceptions (`\RuntimeException`, `\DomainException`, `\InvalidArgumentException`) with a plain message — there are no custom Exception classes and no custom handling in `bootstrap/app.php`. Controllers guard access with `abort_unless()`/`abort_if()`; validation-shaped failures outside `$request->validate()` use `ValidationException::withMessages([...])`. See `app/Services/InvoiceBuilderService.php`, `app/Http/Controllers/TenantPortalController.php`.
- Relationship methods are explicitly return-typed (`BelongsTo`, `HasMany`, ...) and grouped under a `// --- Relationships ---` banner. Denormalized-column sync (e.g. cached `property_id`/`landlord_id`) happens in `protected static function booted()` via `creating`/`saving`/`saved`/`deleted` closures, not in a controller or service. See `app/Models/Invoice.php`, `app/Models/Rental.php`.

### Filament admin panel

- Both panels (`AdminPanelProvider`, `LandlordPanelProvider`) explicitly whitelist `->resources()`/`->pages()`/`->widgets()` — no auto-discovery. Register a new resource in the matching PanelProvider, not just by adding the file.
- Wrap row actions in a single `Tables\Actions\ActionGroup` with `->icon('heroicon-m-ellipsis-vertical')->label(null)->color('gray')` — never bare inline `ViewAction`/`EditAction`/`DeleteAction`. See `app/Filament/Resources/PropertyResource.php`.
- Every UI string goes through `__()`, keyed in the single flat `lang/km.json` (no per-panel/per-resource lang files, no `lang/en`). `AppServiceProvider::boot()` globally applies `->translateLabel()` to Field/Column/BaseFilter, so even auto-generated labels get translated — but you must still add the exact English string as a key to `lang/km.json` or it renders untranslated.
- Enums backing a Select/Filter/Badge implement `HasLabel`/`HasColor`; pass the enum class directly as `->options(EnumClass::class)` rather than building option arrays inline. See `app/Enums/RentalStatus.php`.
- A resource whose model is property-scoped uses the `ScopesToActiveProperty` trait (`app/Filament/Concerns/ScopesToActiveProperty.php`); widgets use `HasActivePropertyScope`. Override `applyActivePropertyScope()` when the model has no direct `property_id` column.
- Shield permissions come from Policies (`policies_and_permissions` generator), not per-resource config — most resources do **not** implement `HasShieldPermissions`. Only add it + `getPermissionPrefixes()` for one extra custom action permission beyond CRUD, following `app/Filament/Resources/UnitResource.php`'s `generate_rooms` example.
- A resource excluded from Shield generation because it already has a hardcoded permission check must be listed in `config/filament-shield.php`'s `exclude` array with a comment explaining why (see `ActivityLogResource`).
- A Select defaulted to the active property and hidden when in context does not reliably dehydrate when hidden — re-inject the value as a fallback in the page's `mutateFormDataBeforeCreate()`. See `app/Filament/Resources/UnitResource/Pages/CreateUnit.php`.

### Frontend / styling

- Filament panel styling goes in `public/css/rentwise-admin.css` — raw CSS targeting Filament's `fi-*` classes or `rw-`-prefixed custom classes/tokens. No build step, no Vite/Tailwind for Filament panels; the file is injected via a `HEAD_END` renderHook with `?v=filemtime(...)` cache-busting (see `app/Providers/Filament/AdminPanelProvider.php`).
- Any hand-authored static asset served straight from `public/` (not through Vite) is referenced as `asset('css/foo.css').'?v='.@filemtime(public_path('css/foo.css'))` for cache-busting — same pattern for `rentwise-loader.css`/`.js` in `resources/views/components/rw-loader-head.blade.php`.
- Filament panels load Filament's own precompiled Tailwind, which only contains classes Filament's components happen to use. An arbitrary Tailwind utility written in a custom Blade/Livewire view inside a panel (`rounded-2xl`, `sm:grid-cols-2`, `text-[10px]`, etc.) can silently compile to nothing. Either confirm the class exists in `public/css/filament/filament/app.css`, or hand-write the rule in `rentwise-admin.css` scoped under a `.rw-*` wrapper.
- Custom classes/CSS vars are prefixed `rw-` (feature sub-prefixes like `rw-mb-`, `rw-invoice-`). Dark-mode overrides for most `rw-*` rules use `.fi.dark .rw-*` (Filament toggles `dark` on the same `<html class="fi ...">` element, so `.fi.dark` and bare `.dark` are equivalent here) — but the `.rw-simple` block (~165 lines, "Simple Mode" pages) deliberately uses bare `.dark .rw-simple ...` selectors to patch Tailwind utility classes missing from Filament's precompiled CSS. Follow `.fi.dark` for new rules by default; don't "fix" the `.rw-simple` bare-`.dark` block if you encounter it — it's intentional (see the comment above it in `rentwise-admin.css`).
- Three separate, non-interchangeable styling pipelines exist — don't cross them: Filament panels (`rentwise-admin.css`, no build), welcome/auth pages (real Vite + Tailwind 4 via `resources/css/app.css`, CSS-first `@theme`, no `tailwind.config.js`), and the tenant portal (`resources/views/portal/layout.blade.php`, Tailwind CDN script, browser-JIT, no relation to the Vite build — `@theme` customizations in `app.css` do **not** apply there).
- 58mm thermal print (client-side) toggles a `print-58mm-active` class on `<body>` via `rwPrintInvoice58mm()` in `resources/views/components/rw-print-script.blade.php` right before `window.print()`, using `@media print` + visibility tricks scoped to `.rw-invoice-wrap`. This is unrelated to the server-side `58mm` PDF size in `App\Support\InvoicePaper` — grep both `'print-58mm'` and `"'58mm'"` before touching either.

### Testing

- Plain PHPUnit, class-based, `test_snake_case` methods — no Pest. `tests/Feature` (DB/Filament/Livewire/HTTP/artisan) is the default; `tests/Unit` is only for pure-PHP logic with no framework/DB dependency.
- Build fixtures with explicit `Model::create([...])`, not factories — only `database/factories/UserFactory.php` exists. See `tests/Feature/GenerateRentInvoicesUtilityBillingTest.php`'s `createBillingFixture()`.
- Any test hitting a landlord-panel resource/page must call `Filament::setCurrentPanel(Filament::getPanel('landlord'))` in `setUp()` and `ActiveProperty::clear()` in `tearDown()` (plus `ActiveProperty::set($property->id)` when property-scoped). See `tests/Feature/MonthlyBillingTest.php`.
- Tests touching role-gated routes seed first: `$this->seed(RolesAndPermissionsSeeder::class);` then `$user->assignRole('landlord'|'tenant'|...)`.
- Test Filament resources/pages through `Livewire::test(PageClass::class, ...)` with Filament assertions (`assertCanSeeTableRecords`, `callAction`, `assertHasNoActionErrors`), not raw HTTP requests.
- Date-sensitive tests use `Carbon::setTestNow('YYYY-MM-DD HH:MM:SS')` in `setUp()` and reset with `Carbon::setTestNow();` in `tearDown()`.
- Assert artisan commands with `->assertSuccessful()` plus `assertDatabaseHas`/`assertDatabaseMissing`, not console-output text; test billing-command idempotency by running the command twice and asserting no duplicate rows.
- A test class/method that codifies a non-obvious decision or regression carries a docblock explaining *why*, not just what. See `tests/Feature/InvoiceBatchPdfTest.php`.

### Data model

- Any model with a `landlord_id` column must `use BelongsToLandlord`. **Exception:** `Payment` has no `landlord_id`, no `BelongsToLandlord`, and no soft deletes — scope through `payment.invoice.landlord_id`; it cascade-deletes with its invoice. All payment writes go through `Invoice::recordPayment()`, never a direct write to `Invoice::amount_paid`. See `database/migrations/2026_06_21_100013_create_payments_table.php`.
- A child model that derives a parent's monetary total recomputes the parent inside its own `booted()` saved/deleted hooks (see `app/Models/InvoiceLine.php`, `app/Models/Payment.php`) — never let the parent's writer set the aggregate directly.
- Status/type enums are `int`-backed, implement `HasColor`+`HasLabel`, and back an `unsignedTinyInteger` column with a `->default(N)` documented inline (`// EnumName: Case=N`).
- Money columns are `decimal(12,2)` (USD-scale, cast `'decimal:2'`) with a KHR twin column (`amount_khr` etc., cast `'decimal:0'`) plus an `exchange_rate` — never a bare float. Conversion goes through `App\Support\Money::normalize()` using the record's saved rate, not a live lookup. See `app/Models/Invoice.php`.
- Platform-subscription billing (`Subscription`, `SubscriptionPlan`, `SubscriptionHistory`, `SubscriptionPayment`) is deliberately unconnected to rent billing (`Invoice`, `Payment`, `InvoiceLine`) — no FK between them. Never add a `subscription_id`/`plan_id` FK onto `Invoice`/`Rental`/`Property`, per `docs/SUBSCRIPTIONS.md`'s "Domain Boundary".
- `rentals.active_unit_id` is a MySQL STORED GENERATED column enforcing "one active tenancy per unit" at the DB layer — never add it to `Rental::$fillable`; `TenancyService::hasOverlap()`/`hasActiveTenancy()` is the app-layer fallback and must stay authoritative if you touch tenancy-overlap logic.
- `Property::total_rooms`/`total_floors` are deliberately computed Attributes over the `units()` relation (anti-drift fix), not persisted columns — don't add a migration column or write to them.
- Seeders use `firstOrCreate()` keyed on a natural/business key (not `id`) so they're safely re-runnable, wrapped in `DB::transaction()`. See `database/seeders/LandlordPortfolioSeeder.php`.
- Migrations for one feature/batch of work share the same date and use a fake sequential suffix (`_100001`, `_100002`, `_100003`...) instead of true per-file timestamps, so a whole feature's schema lands together and stays ordered. See `database/migrations/2026_06_28_100001_create_subscription_plans_table.php`.
- A denormalized FK added purely for scoping/relation-manager convenience gets an inline `// DENORMALIZED for scoping` comment at the column and is kept in sync via a `static::saving()`/`booted()` hook on the child model, not left to drift. See `database/migrations/2026_06_21_100011_create_invoices_table.php`.

### Project-level decisions (docs/)

- Hard-coded Khmer text is fine for actual data values, but never for UI chrome (labels, nav, actions, validation messages) — those must go through `__()` with the string added to `lang/km.json`, per `docs/LOCALIZATION.md`.
- Subscription access state (`SubscriptionService::effectiveAccess()`) is computed on read, never persisted as a synced "current status" column a cron has to keep updated — stored `status` is intent, effective access is computed per-request.
- Subscription enforcement middleware applies only to the landlord panel — tenants are never blocked from portal login/rent payment by their landlord's subscription status ("tenants always win"). See `docs/SUBSCRIPTIONS.md`.
- Terms that affect an in-progress agreement (e.g. subscription plan pricing) are snapshotted onto the child record at assignment time; editing the parent template must never retroactively change an already-active record.
- New policy toggles (move-in requirements, charges, deposits) are modeled as structured/enum-driven rule records, not a new boolean column per variant. See `app/Models/MoveInRule.php`, `app/Enums/MoveInChargeType.php`, `docs/MOVE_IN_BILLING_RULES.md`.

## PDF / invoice generation

Invoice/report PDFs render through **Browsershot** (headless Chrome via Puppeteer) as the primary path in `InvoicePdfService::render()`, with an automatic silent fallback to `barryvdh/laravel-dompdf` on any `Throwable`. Config is pulled from `config('services.browsershot.*')` (chrome_path/node_binary/npm_binary/etc.); replicate this full block (not `Browsershot::html(...)->pdf()` bare) for any new Browsershot PDF — `ExportUtilityUsagesJob::generatePdf()` duplicates it rather than reusing the service, so prefer extracting a shared helper before copying it a third time.

- `App\Support\InvoicePaper` is the single source of truth for paper-size metadata (mm widths, dompdf paper boxes, labels, `isThermal()`) — extend it, don't duplicate size logic in controllers/services/views.
- Any Blade view rendered to PDF must declare `NotoSansKhmer` via two `@font-face` rules pointing at `resource_path('fonts/NotoSansKhmer-Regular.ttf')`/`-Bold.ttf` (dompdf needs a filesystem path, not `asset()`/Google Fonts), and use table-based layout only — no flexbox/grid, since dompdf is a live fallback renderer, not just a historical option. See `resources/views/invoices/pdf.blade.php`.
- `resources/views/invoices/pdf.blade.php` formats money via a local `$formatPdfMoney`/`$money` closure using `Money::normalize()` (0 decimals KHR, 2 decimals USD) and dates via `Invoice::displayDate()` (ASCII `-` fallback). The other two dompdf report views sharing its Khmer `@font-face` block (`reports/utilities-pdf.blade.php`, `reports/utility-usages-pdf.blade.php`) do **not** follow this — they use plain `number_format()` with a hardcoded `$` (no KHR support) and raw `->format('Y-m-d')` with an em-dash fallback. Don't assume the money/date helper pattern extends beyond the invoice template; port `Money::normalize()`/`displayDate()` in if a report PDF needs KHR-aware formatting rather than copying the report views' current ad hoc `number_format()`.
- The logo comes from `App\Support\BrandLogo::dataUri()` (base64-inlined), never a plain `<img src>` path.
- `InvoiceDocumentController::pdf()` logs the request's app/session/cookie locale via `Log::info` on every request — that's leftover debug instrumentation, not a stable logging convention; don't copy it into new controller actions.
- dompdf ignores `@page { margin }` — set padding on `<body>` for standard layout (thermal stays edge-to-edge via `.wrap` padding).
- The batch/print-all PDF (`InvoicePdfService::makeBatch`) renders the same single-invoice Blade view per invoice and regex-splices out `<style>`/`<body>` rather than a separate multi-invoice template — preserve this for any new "print many" PDF.
- Excel export uses two different libraries by design, not accident: `app/Services/InvoiceExcelExport.php` (single-invoice streamed download) uses `openspout/openspout`; `app/Jobs/ExportUtilityUsagesJob.php` (multi-sheet queued report to `storage/app/exports`) uses `phpoffice/phpspreadsheet`. Match the library to the export's shape rather than consolidating onto one.
- The `@font-face` Khmer font pair is duplicated verbatim across `resources/views/invoices/pdf.blade.php`, `resources/views/reports/utilities-pdf.blade.php`, and `resources/views/reports/utility-usages-pdf.blade.php` (no shared partial). Copy the exact block into any new dompdf-rendered view with Khmer content — there is nothing to `@include` yet.
- **Gotcha (load-bearing):** Browsershot failures are swallowed silently — a warning-only log line, then a dompdf-rendered PDF with mangled/tofu Khmer text and an initials-only logo, no user-facing error. dompdf cannot shape Khmer script at all. Fix: `chrome-headless-shell` must be installed per-machine (`npx puppeteer browsers install chrome-headless-shell` as the PHP user), or set `BROWSERSHOT_CHROME_PATH`/`BROWSERSHOT_NODE_BINARY` in `.env`. Verify by generating a PDF and grepping `storage/logs/laravel.log` for `Browsershot invoice PDF render failed`.

## Known pitfalls

- **Dev server is 4x slower than it should be.** The `php` on PATH is a static herd-lite build with no OPcache (PHP 8.4.1, `pcre.jit=0`) → ~300ms+/req, and it's missing `pdo_mysql` on 8.4. Always serve with `PHP_CLI_SERVER_WORKERS=6 /usr/bin/php8.3 artisan serve --port=8002` (`/usr/bin/php8.3` has OPcache + `pdo_mysql`). `PHP_CLI_SERVER_WORKERS` matters because Livewire fires concurrent requests. Run `artisan icons:cache`, `filament:cache-components`, `view:cache`, `composer dump-autoload -o` after adding icons/Livewire components — but do **not** cache config/routes during active dev (stale-`.env` foot-gun).
- **Test suite OOMs under default memory_limit.** `php artisan test` (128M default) reliably dies with "Allowed memory size... exhausted" partway through the Feature suite. Run `php -d memory_limit=1G artisan test` for the full suite (filtering to a single class with `--filter` usually stays under 128M).
- **Filament palette alpha syntax silently breaks.** In `public/css/rentwise-admin.css`, Filament emits palette channels comma-separated (e.g. `--gray-950: 2, 6, 23`), so `rgb(var(--gray-950) / 0.55)` expands to malformed CSS (`rgb(2, 6, 23 / 0.55)`) and the browser silently drops the whole declaration to transparent — no error. Use `rgba(var(--gray-950), 0.55)` instead. Literal space-separated forms like `rgb(15 23 42 / 0.05)` are fine. Verify with `grep -nE "rgb\(var\(--[a-z0-9-]+\) */ *[0-9.]+\)" public/css/rentwise-admin.css` — must return nothing.
- **Invoice PDF Khmer rendering depends on Browsershot succeeding.** See the PDF section above — a mangled-Khmer PDF is a Browsershot/chrome-headless-shell problem, not a template bug; check the log warning before touching the Blade view.
- **`accent-color` does nothing on `.rw-mb` checkboxes.** `@tailwindcss/forms` sets `appearance: none` and paints the checked box via `currentColor`, so `accent-color` alone is silently ignored — set both `color` and `accent-color` together (see the `.rw-mb input[type="checkbox"]` rule in `rentwise-admin.css`).
- **No Form Request classes, no `app/Actions` for app code, no model factories beyond `User`.** All three are easy reflexes from typical Laravel conventions that are off-convention here — see the Backend/Testing sections above.
- **`PropertyResource`'s Address section has mislabeled fields** (`village` labeled "Province / City", `commune` labeled "Landlord", `district` labeled "Units" — clearly copy-pasted). If you touch this section, fix the labels; don't copy it as a reference pattern for a new resource. See `app/Filament/Resources/PropertyResource.php`.
- **5 `Notification::title()` call sites use a raw, untranslated string** while ~43 others in the app correctly wrap in `__()`: the 4 renew/upgrade/schedule/cancel notifications in `app/Filament/Pages/Billing.php`, plus `UnitResource.php`'s `generate_rooms` bulk action (~line 591). If you touch any of these actions, wrap the string and add its key to `lang/km.json` — don't treat `Billing.php` as the only offender.
- **`ai-tasks/*.md`, `TASK_PWA.md`, `UTILITY_EXPORT_PLAN.md`, `58mm_print_instructions.md` are historical specs, not a live backlog** — nearly all describe work already implemented. Grep the codebase for the files/symbols a task names before treating it as current. `todo.md` (hidden/zero-display charge-state test coverage) and `docs/ROADMAP.md`'s "incomplete/limited" sections are the actual open backlog. `prompt.md` (an "Obsidian dol ngai" vault template) is unrelated leftover — ignore it entirely.
- **`graphify-out/` is stale** (generated 2026-07-10, many commits behind). Don't trust it for anything touched by recent invoice/report work; cross-check against current source.

## Before finishing a task

- Run the relevant tests: `php -d memory_limit=1G artisan test` for the full suite, or `php artisan test --filter=SomeTest` for a targeted run (plain `php artisan test` will OOM on the full suite).
- If you touched `public/css/rentwise-admin.css`, run `grep -nE "rgb\(var\(--[a-z0-9-]+\) */ *[0-9.]+\)" public/css/rentwise-admin.css` and confirm it returns nothing.
- Run `vendor/bin/pint --dirty` (no `pint.json` — default Laravel ruleset; nothing in CI enforces this, so it's on you).
- If you added/changed a Filament label, Notification title, or any user-facing string, add its key to `lang/km.json` — verify with `grep '"Your Exact String"' lang/km.json`.
- If you touched invoice/report PDF templates, `InvoicePdfService`, or Browsershot config, generate a PDF and grep `storage/logs/laravel.log` for `Browsershot invoice PDF render failed` to confirm it rendered via Chrome, not the dompdf fallback — a passing test doesn't catch a silent Khmer-mangling fallback.
- If you added a model with a `landlord_id` column, confirm it uses `BelongsToLandlord` (or is deliberately scoped like `Payment`).
- After adding new icons or Livewire components, run `artisan icons:cache`, `filament:cache-components`, `view:cache`, `composer dump-autoload -o` — but don't leave config/routes cached afterward.
